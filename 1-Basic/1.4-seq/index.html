Flip-flops in SystemVerilog

~8 min

A register is a flip-flop that copies its input on a clock edge. You always write it with always_ff and the non-blocking assignment <=:

register.sv
always_ff @(posedge clk) begin      // "on every rising edge of clk..."
    q <= d;                         // "...q takes the value d" (all <= of the block update together)
end

// a counter: the register feeds itself through an adder (it uses the carry cells of module 1.1)
always_ff @(posedge clk)
    if (en) cnt <= cnt + 1'b1;      // no else: without a branch the register simply keeps its value

// a shift register: every <= reads the OLD values, so this really shifts by one place
always_ff @(posedge clk)
    sr <= {sr[2:0], din};

Why <= and not =

All right-hand sides of a clocked block are evaluated before any register changes. That is exactly how hardware behaves: every flip-flop samples at the same instant. With the swap below both registers exchange values, like two real flip-flops would:

swap.sv
always_ff @(posedge clk) begin
    a <= b;      // b and a are both read first ...
    b <= a;      // ... so this is a true swap
end
// with blocking "=" the second line would read the NEW a: both would end up equal to b. Not hardware.

Reset: asynchronous or synchronous

resets.sv
// asynchronous, active low: the flip-flop clears as soon as rst_n falls, no clock needed
always_ff @(posedge clk or negedge rst_n)
    if (!rst_n) q <= 1'b0;
    else        q <= d;

// synchronous: the reset is just one more input of the logic; it acts on a clock edge
always_ff @(posedge clk)
    if (!rst_n) q <= 1'b0;
    else        q <= d;

// no reset at all: an initial value, loaded together with the bitstream
logic q = 1'b0;

On the Tang Nano the initial value is the cheapest "reset": the flip-flop starts at that value as soon as the bitstream loads. Use a reset signal when something must be able to return to the start while running (a button, an error).

Slow things: ticks, not clocks

~5 min

The clock runs at 27 MHz; your eyes and fingers live at a few hertz. To make something happen once a second you do not create a slow clock (that makes timing analysis and the global clock network miserable). You keep the fast clock everywhere and generate a tick: a pulse exactly one clock cycle wide, once every CLK_HZ / TICK_HZ cycles. Slow logic updates only on the cycles where tick = 1.

tick_use.sv
// slow logic = fast clock + clock enable
always_ff @(posedge clk)
    if (tick) pos <= pos + 1'b1;          // moves 6 times per second if the tick is 6 Hz

For CLK_HZ = 27_000_000 and TICK_HZ = 6 the divider counts 4_500_000 cycles, which needs $clog2(4_500_000) = 23 bits.

Buttons: metastability, bounce and edges

~8 min

A button is the first asynchronous input you meet: it can change at any instant, even right when the clock samples it, and mechanical contacts also bounce (they open and close several times in about a millisecond). Three small circuits fix this, always in the same order:

  1. Synchronizer: two flip-flops in series. If the first one samples at the wrong moment and becomes metastable (neither 0 nor 1 for a while), it has a whole clock period to settle before the second one looks at it.
  2. Debounce: accept a new level only when it has been stable for a few milliseconds.
  3. Edge detector: turn the clean level into a one-cycle pulse on each press, so that holding the button counts once.

Explore the debounce: choose how long the contacts bounce and how long the circuit waits.

Debounce visualizer

The circuit gets fooled when a quiet gap inside the bounce lasts longer than the debounce time, so the safe rule is to wait longer than the whole bounce. Real buttons usually bounce for well under 5 ms; 10 ms is a comfortable value. A longer time only makes the button feel slower.
