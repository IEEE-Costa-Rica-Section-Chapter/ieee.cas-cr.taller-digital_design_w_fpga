Combinational building blocks

~8 min

Every combinational circuit of your theory course has a short SystemVerilog form. Keep two habits: assign every output in every branch (no latches) and write what you mean (a case for a decoder, a ?: for a 2-way choice).

blocks.sv
// 3-to-8 decoder (one-hot): shift a 1 to the position given by sel
assign onehot = 8'b00000001 << sel;

// priority encoder: the HIGHEST request wins; "valid" says that any request exists
always_comb begin
    valid = 1'b1;
    if      (req[3]) idx = 2'd3;
    else if (req[2]) idx = 2'd2;
    else if (req[1]) idx = 2'd1;
    else if (req[0]) idx = 2'd0;
    else begin idx = 2'd0; valid = 1'b0; end      // every output assigned in every branch
end

// comparator and 2-way multiplexer
assign lt  = (a < b);
assign max = (a < b) ? b : a;

// adder with carry: widen BEFORE adding, or the carry is lost
assign {cout, sum} = {1'b0, a} + {1'b0, b};

An unique case tells the tools that exactly one branch matches (they may then build a smaller circuit and warn you in simulation if two match). A plain case with a default is always safe to start with.

How an adder really works: ripple carry

~6 min

In Module 1.1 you saw that an FPGA has a dedicated carry chain. Here is the idea it implements: one full adder per bit, each passing its carry out to the next one's carry in. Toggle the bits and watch the carry ripple.

3-bit ripple-carry adder

You write the + operator and the tools build this chain on the carry cells. The generate version (three explicit full adders) is an extra exercise below.

Lab 1.3: a 3-bit adder and a small ALU

~14 min

Open 1-Basic/labs/alu. You write two modules, in this order. Both have exhaustive testbenches: all 64 pairs for the adder, all 256 combinations for the ALU (only 8 input bits: cheap enough to try everything).

Part a: src/adder3.sv

src/adder3.sv (your work)
// adder3.sv - LAB 1.3a: a 3-bit adder with carry out.
//   {cout, sum} = a + b        (a, b, sum are 3 bits wide, cout is 1 bit)
// Hint: the sum of two 3-bit numbers needs 4 bits. Write the + on a 4-bit result,
// or build it from three full adders if you want to practise `generate`.
module adder3 (
    input  logic [2:0] a,
    input  logic [2:0] b,
    output logic [2:0] sum,
    output logic       cout
);
    // TODO
    assign sum  = 3'b000;
    assign cout = 1'b0;
endmodule

Part b: src/alu3.sv

The adder is already instantiated inside the ALU. You choose y and carry from op and compute the zero flag.

src/alu3.sv (your work)
// alu3.sv - LAB 1.3b: a small ALU on 3-bit operands.
//
//   op = 00  y = a + b (mod 8), carry = carry out of the addition
//   op = 01  y = a & b          carry = 0
//   op = 10  y = a | b          carry = 0
//   op = 11  y = a ^ b          carry = 0
//   zero = 1 when y == 0
//
// The adder is already instantiated for you. Rules for always_comb:
//   * give EVERY output a value in EVERY branch (or a default before the case),
//     otherwise the tools infer a latch (see lab 1.2b).
module alu3 (
    input  logic [2:0] a,
    input  logic [2:0] b,
    input  logic [1:0] op,
    output logic [2:0] y,
    output logic       carry,
    output logic       zero
);
    logic [2:0] sum;
    logic       cout;
    adder3 u_add (.a(a), .b(b), .sum(sum), .cout(cout));

    always_comb begin
        // TODO: choose y and carry according to op
        y     = 3'b000;
        carry = 1'b0;
    end

    // TODO: zero flag
    assign zero = 1'b0;
endmodule

On the board

make prog: the sweep gives a and b every possible value (four steps per second, 16 seconds for all 64 pairs). LED0–LED2 show y, LED3 the carry, LED4 the zero flag. Change the constant OP in src/top.sv, rebuild, and watch another operation.

📝
Why the board cannot show the inputs

The board has only six LEDs. You cannot see a and b and the result at the same time. That is exactly why the simulation matters: the testbench looks at all 256 cases in a fraction of a second, which no one could do by watching LEDs.
