Mini-project: a light show

Combine the button path, ticks, a state machine and a multiplexer into one design.

  • Verify each block with its testbench, then the whole on the board

The project: a three-mode light show

~4 min

Put everything together. Button S1 switches between three light shows on the six LEDs:

ModeWhat the LEDs doBuilt from
0Knight Rider: a light bouncing across the LEDstick_gen + knight (module 1.4)
1All LEDs blink together, once per secondtick_gen + a toggle flip-flop
2A binary counter, four steps per secondtick_gen + a counter

The whole design, as blocks:

architecture
S1 --> [sync2] --> [debounce] --> [rise_detect] --press--> [mode_fsm] --mode--+
                                                                        |
tick 8 Hz --> [knight] -------------------------knight pattern-----+    v
tick 2 Hz --> [blink toggle] ------------------------blink-----------> [show] --> LEDs
tick 4 Hz --> [counter] -----------------------------count-----------+

Everything except two blocks is already in src/ (the button path and the tick generators are the reference versions of what you wrote in module 1.4, and top.sv wires them). You write the two blocks in the middle: mode_fsm (a 3-state machine) and show (a multiplexer on the mode).

Build it

~18 min

Open 1-Basic/labs/light-show.

src/mode_fsm.sv (your work)
// mode_fsm.sv - MINI-PROJECT part 1: which light show is running?
//
// Three modes, 0 -> 1 -> 2 -> 0 -> ..., advancing by ONE step on every cycle
// where `next` = 1 (a one-cycle pulse from the debounced button).
// Between pulses the mode must not change. rst_n returns to mode 0.
//
// Use a two-process state machine as in module 1.5. Moore: `mode` depends only on the state.
module mode_fsm (
    input  logic       clk,
    input  logic       rst_n,
    input  logic       next,
    output logic [1:0] mode
);
    // TODO: states, state register, next-state logic, output
    assign mode = 2'd0;
endmodule
src/show.sv (your work)
// show.sv - MINI-PROJECT part 2: choose what the LEDs display. Purely combinational.
//
//   mode 0 : the knight-rider pattern      -> leds = knight
//   mode 1 : every LED blinks together     -> leds = {6{blink}}
//   mode 2 : a binary counter              -> leds = count
//   mode 3 : not used, all LEDs off        -> leds = 6'b000000
//
// leds is ACTIVE-HIGH (1 = lit); the top inverts it. No latches: cover every mode.
module show (
    input  logic [1:0] mode,
    input  logic [5:0] knight,
    input  logic       blink,
    input  logic [5:0] count,
    output logic [5:0] leds
);
    // TODO
    assign leds = 6'b000000;
endmodule
  1. make sim TB=mode_fsm: presses must walk the mode 0 → 1 → 2 → 0, and nothing changes between presses.
    before you write it
    FATAL: tb/mode_fsm_tb.sv:29: after 1 presses mode=0, expected 1
  2. make sim TB=show: exhaustive over the mode and many patterns. Remember: every mode must assign leds, including mode 3.
  3. make sim prints PASS twice. Then make prog.
  4. Press S1: Knight Rider, then all LEDs blinking together, then the binary counter, then back to Knight Rider.
📝
How big is it?

When you run make build the report lists the whole design. It is far larger than anything so far (about 170 LUT4 and 100 flip-flops in the reference solution), and still less than 1% of the chip. Three tick generators with 20+ bit counters make up most of it.

What you built in Level 1

~3 min

In three hours you went from a theory course to a design you can touch:

  • How the chip works: LUTs, logic cells, carry chains and the bitstream that configures them.
  • Combinational logic with assign and always_comb, tested exhaustively.
  • Sequential logic: registers, ticks, a synchronizer, debounce and edge detection.
  • State machines in the two-process style, verified against a reference model with random stimulus.
  • The whole loop: write → simulate → build → program, with self-checking testbenches deciding when you are done.

Optional extras

  • Rebuild adder3 from full adders with generate (lab 1.3).
  • Turn the detector into a Mealy machine, or make it detect 1011 or 1101.
  • Add a fourth mode to the light show.
  • Write a testbench of your own for a module that has none yet (top.sv is a good candidate).

Wrap-up
1.6.Q

Checkpoint

3 questions. You need all of them right; you can retry as often as you like.

1. Which block of the light show has memory?

2. One press of S1 must change the mode by exactly one step, however long it is held. Which module guarantees that?

3. The mode changes when you release S1 instead of when you press it. What do you change?
