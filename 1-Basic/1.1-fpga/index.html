What an FPGA is

~4 min

In a theory course you drew gates and flip-flops on paper. A Field-Programmable Gate Array is a chip that can become that drawing: it contains thousands of small, identical logic blocks and a network of wires with programmable switches between them. You do not wire gates; you load a configuration that decides what each block computes and which switches are closed.

On the Tang Nano 20K the chip is a Gowin GW2AR-18. You saw its totals in the Module 0 report: 20,736 LUT4, 15,552 flip-flops, 384 I/O blocks and 24 global clock buffers.

The configuration lives in volatile memory

The bitstream is stored in SRAM cells inside the chip, so it is lost when power is removed. That is exactly the difference between the two programming commands you met in Module 0: make prog loads the bitstream straight into the SRAM (instant, gone at power-off) and make flash also stores it in the board’s SPI flash, from which the FPGA reloads itself at every power-up.

📝
Hardware description, not a program

A CPU runs your code one instruction after another. SystemVerilog does not run: it describes circuits, and every circuit you describe exists at the same time and works in parallel. Keep this in mind from the first line you write.

The LUT4: a truth table in a memory

~7 min

The basic piece of combinational logic is the look-up table with 4 inputs (LUT4). Inside it there is no gate at all. It is built from two things:

  • 16 SRAM cells, each holding one bit. These bits are the truth table of the function: the value the output must have for each of the 16 input combinations.
  • A tree of 15 two-way multiplexers that picks one of those 16 bits. The four inputs a, b, c, d do not compute anything: they are the select lines of the multiplexers. Input a steers the first column (16 candidates become 8), b the second (8 become 4), c the third and d the last, which leaves a single bit: the output y.

So a LUT does not compute a function, it looks it up. Different function = different 16 bits, same hardware.

Inside a LUT4, and how it is reconfigured

1. Toggle the inputs (the round buttons a b c d) and follow the bright path from one stored bit to the output. 2. Choose a function and press Load: the 16 bits are written into the SRAM cells one by one, exactly what the bitstream does to every LUT of the chip. 3. Use the View buttons to switch to the same function drawn as logic gates, and back: the two views always give the same output.

The LUT now implements

Reconfiguring = rewriting 16 bits

Loading a bitstream into the FPGA writes SRAM cells like these, millions of them: 16 bits for every LUT, plus the bits that close the routing switches and set every I/O block. Nothing is soldered and nothing moves. That is what “field-programmable” means, and it is why the same chip can be a counter now and an adder after the next make prog.

Three consequences you will use all course long:

  • Any function of up to 4 inputs costs exactly one LUT4, however many gates it needs on paper: with 16 stored bits you can store any of the 216 = 65,536 truth tables.
  • A function of more than 4 inputs is split across several LUTs connected in series (on paper an 8-input XOR needs three small LUTs: two for the halves, one to combine them). The fabric can also join LUTs with built-in multiplexers into wider LUTs (LUT5 to LUT8), which is what the tool uses by default.
  • Delay does not depend on how complicated the function is, only on how many LUTs a signal passes through and how far apart they are placed.

The logic cell: LUT + flip-flop

~5 min

A LUT alone can only give combinational logic. Next to every LUT the chip places a D flip-flop, and a multiplexer chooses what the cell outputs: the LUT directly (combinational) or the flip-flop (registered). That multiplexer is steered by one more configuration bit, stored in SRAM just like the 16 bits of the LUT. This single choice is the whole difference between the two kinds of logic you studied.

One logic cell

The LUT is the one from the previous step (shown here as its 16 stored bits). Toggle the inputs, press clock edge, and click the select bit to switch between combinational and registered output.

LUT contents

With the select bit at 0, change the inputs: the output follows at once. With it at 1, the output stays put when you change the inputs; the flip-flop copies the LUT output only on the clock edge. This is why counters, state machines and shift registers cost flip-flops, while purely combinational circuits cost only LUTs.

A third kind of cell: carry logic

Adders and counters would waste many LUTs and be slow if each carry travelled through general routing. So the fabric has a dedicated carry chain: in the Gowin chip these cells are called ALU in the nextpnr report (do not confuse them with a CPU’s ALU). Yosys maps + and counter increments onto them automatically. You saw 26 of them in the blink report of Module 0.

Why this matters for your code

When you write q <= q + 1 you are choosing flip-flops and carry cells; when you write a case you are filling LUTs. Learning to predict the resource count of what you write is the first skill of an FPGA designer, and the lab below trains it.

Lab: predict, then measure

~8 min

Three tiny designs are in the lab project 1-Basic/labs/fpga-anatomy (open that folder in VSCode, as in Module 0). For each one, predict how many LUT4, ALU (carry) cells and flip-flops (DFF) Yosys will use, then measure.

src/xor4.sv
// xor4.sv - experiment 1: one 4-input function.
module xor4 (
    input  logic [3:0] a,
    output logic       y
);
    assign y = ^a;      // XOR of all four bits
endmodule
src/adder8.sv
// adder8.sv - experiment 2: an 8-bit adder (combinational).
module adder8 (
    input  logic [7:0] a,
    input  logic [7:0] b,
    output logic [8:0] sum      // 9 bits: the extra bit is the carry out
);
    assign sum = a + b;
endmodule
src/counter8.sv
// counter8.sv - experiment 3: an 8-bit counter (sequential).
module counter8 (
    input  logic       clk,
    input  logic       rst_n,   // asynchronous, active low
    output logic [7:0] q
);
    always_ff @(posedge clk or negedge rst_n)
        if (!rst_n) q <= '0;
        else        q <= q + 8'd1;
endmodule

2. Measure

The new target make stat runs synthesis only (no pins needed) for any module. Run it once per design:

VSCode terminal, in the lab folder 
make stat TOP=xor4
make stat TOP=adder8
make stat TOP=counter8

Look for the lines LUT4, ALU and DFFC in the cell list. Ignore IBUF/OBUF (the pin buffers), GND/VCC (constants) and LUT1 (one-input glue cells). For reference, this is the counter:

make stat TOP=counter8 (excerpt) 
        8   ALU
        8   DFFC
        2   IBUF
        2   LUT1
        8   OBUF
📝
What are those names?

DFFC is the Gowin D flip-flop with an asynchronous clear, which is how Yosys implements our negedge rst_n reset. The adder has 9 carry cells because it computes 9 result bits (8 sum bits and the carry out). The counter uses carry cells for the + 1 and has no LUT4 at all: carry logic is cheaper than a LUT for this job.

3. Explain

Discuss with your neighbour or write one line each:

  • Why does the 4-input XOR need one LUT4 although it is three XOR gates on paper?
  • Why does the adder use zero flip-flops and the counter use eight?
  • The counter has 8 outputs but the adder has 9. Where does the extra adder output come from?
